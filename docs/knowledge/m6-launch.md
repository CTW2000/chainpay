# M6 · 上线（2026-09-14 起）

> 目标：把它真的部署到一台机器上，走完部署八环节：构建 → 配置 → 密钥 → 迁移 → 分发 → 切换 → 验证 → 回滚。
> 前五个里程碑攒下来、标着「M6」的账，在这里一次清。

## 〇、这一步为什么现在做

到 M5 为止，系统能收、能付、能对账，但它只在一台开发机的 `nohup java -jar` 里跑，靠人盯。
上线不是「换台机器」，是把「人盯」换成「机器盯」：谁判断它活着、谁判断它能干活、谁在它停下时叫人、
坏了怎么退回上一版、退回时数据库怎么办。这些问题每一个都有一段代码或一段脚本对应。

部署目标（假定，用户可改）：**先在这台 Mac 上用 docker compose 把应用和中间件一起跑起来**，
八个环节全部写成脚本、演练一遍；脚本不依赖 Mac 特有的东西，换到一台 Linux 主机不用改。

## 一、拆成六个小步（每步：红测 → 绿 → 拆墙 → 全套 → 真跑 → 讲）

| 步 | 做什么 | 清的旧账 |
|---|---|---|
| ⓪ 健康检查 | 「活着」与「能干活」分开：`liveness`（进程在）、`readiness`（两个连接池都通、迁移对得上）、`work`（索引器 / 热钱包 / 判官 / Redis 的状态）；只在回环的管理端口上答，不要令牌，不漏细节；两个池的指标进 Micrometer | CLAUDE.md「上线需要两个池的健康检查与指标进监控——手工给 Hikari 绑 Micrometer」 |
| ① 容器化 | 多阶段 Dockerfile（非 root、HEALTHCHECK 打 readiness）、`.dockerignore`、compose 里加 `app` 服务；密钥只从 `env_file` 进，镜像层里 `check-secrets.sh` 扫不到 | LEARNING-PATH M6 五条 |
| ② 停机恢复 | 追赶不受「每轮 10 批」限制（落后越多追得越快，追平后回到常速）；**注资登记**（往热钱包打的钱要有一行记录，托管等式把它算进去，M5 那条 +25 LINK 的差异就此收掉）；监听地址与日志级别按环境来 | M3-⑤「追赶速度」、M5「注资登记」、安全扫描第 15 条 |
| ③ 告警 | 一个通知出口（HTTP webhook，地址只从环境变量来，不设 = 只打日志）：索引器 HALTED / DEGRADED、热钱包 HALTED、对账 DIFF / FAILED / stale、发送任务 HALT；同一件事只叫一次，恢复再叫一次 | M5「告警的载体是 M6」 |
| ④ 部署脚本与回滚演练 | `deploy/` 下八个环节各一个脚本：构建（打镜像并打标签）、配置检查（必填变量齐不齐）、迁移（单独一步，失败即停）、切换（起新容器）、验证（打 readiness）、回滚（回上一个标签）；**真的演练一次回滚** | LEARNING-PATH M6「一条能回滚的路径，并且真的演练一次」 |
| ⑤ 控制面 | 把「回环 + 静态令牌」换成生产级管理员：管理员表、登录（口令用 Argon2id，引库）、短期会话、敏感操作再认证、管理操作审计表 | CLAUDE.md「回来做的条件：开始做 M6」 |

⑤ 最大，放最后；前四步做完系统就已经能无人值守地跑在容器里。

## 二、取舍（我的建议，你定）

| # | 题 | 选项 | 建议 |
|---|---|---|---|
| 1 | 健康检查引不引 Actuator | A 引 `spring-boot-starter-actuator`；B 自己写三个接口 | **A**。分组、探针、HTTP 状态映射、连接池与 Redis 的指示器都是「协议编码」，自己写只会写出一个差的 Actuator；每个指示器**判什么算能干活**是业务，自己写（§7） |
| 2 | 健康检查放哪个端口 | A 主端口 `/actuator/**`；B 独立管理端口，只绑回环 | **B**。探针不能带令牌（进程管理器、容器 HEALTHCHECK 都不会带），放主端口就等于对公网开一个无认证接口；独立端口只绑 127.0.0.1，从外面根本到不了 |
| 3 | readiness 里放什么 | A 只放数据库；B 数据库 + 索引器 + 热钱包 | **A + 系统池**。readiness 回答的是「这个进程能不能接请求」：商户 API 只要两个池通就能答；索引器停了是**要叫人**，不是**下线整个进程**（下线了商户连余额都查不了）。索引器 / 热钱包 / 判官放 `work` 组，给告警和人看 |
| 4 | 索引器 DEGRADED 算什么 | A 算 UP；B 算 DOWN；C 单独一档 | **C**，自定义状态 `DEGRADED`，排在 UP 之前、DOWN 之后，HTTP 200。告警按「不是 UP」触发，容器不重启 |
| 5 | 进程管理器 | A launchd / systemd 管 jar；B Docker 管容器（`restart: unless-stopped`） | **B**。既然要容器化，就让容器运行时当进程管理器，Mac 与 Linux 一致；systemd 只多一个「管 docker compose」的壳，④ 里给出 |
| 6 | 迁移单独跑还是随应用启动 | A 随启动（现状）；B 单独一步 | **B**，但保留 A 做兜底。单独一步的好处：迁移失败时旧版本还在跑、没有切换；随启动失败时新容器起不来、compose 会反复重启它。应用启动时的 `validate-on-migrate` 保留，作为「schema 和代码对不上就不起来」的最后一道 |
| 7 | 注资登记怎么记 | A 只记一张表，托管等式减掉它；B 走账本（`chain:custody` 对 `platform:treasury`） | **A**。注资是链上事实进账本的镜像，和入账同一种性质；走账本要造一个「平台自有资金」账户体系，那是 M7 之后的题 |
| 8 | 告警渠道 | A 邮件；B 通用 webhook；C 两者 | **B**。一个 POST JSON 能接 Slack / 飞书 / 钉钉 / PagerDuty 的入站 webhook；邮件要 SMTP 凭证和一整套投递问题 |
| 9 | 回滚时数据库怎么办 | A 迁移可逆（写 undo）；B 迁移只前进，代码兼容前一版 schema | **B**（expand / contract）。undo 脚本在生产从来没人敢跑；规矩改成「一次发布里的迁移必须让上一版代码也能跑」，④ 的演练就验这一条 |

## 三、不做的

- Kubernetes：一台机器一个 compose 足够；探针接口按 k8s 的约定命名，将来搬过去不用改。
- 多实例：限流已经在 Redis 里，但索引器 / 发送 / 追踪 / 对账四个定时任务都没有分布式锁，两个实例会各跑一份。上线先单实例，多实例是 M7 之后的题。
- 二次验证与冷却期（M4-④ 记的）：依赖 ⑤ 的用户会话，⑤ 做完再评估。
