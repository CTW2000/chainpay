## 一、背景知识

### 1. nonce：每笔交易的编号
外部账户（EOA）只有两样状态：余额和 **nonce**（这个地址已经成功发出的交易数，从 0 起）。网络只接受**恰好等于当前值**的那一笔：发了 0..4，下一笔必须是 5；带 5 的两笔只有一笔能进；带 7 的会被节点放着等 6。
它防重放（没有它，截到一笔签名交易就能反复广播），代价是**编号的真相在链上、不在库里**：库说 next = 12、链说 10，是以为发出去的两笔没到；库说 12、链说 13，是有人用这把私钥在别处发了一笔。
`eth_getTransactionCount(addr, "latest")` 只算已上链的；`"pending"` 再加上**这个节点**内存池里排队的——另一个节点不一定看得到，两者不同的窗口就是并发事故的温床。

### 2. EIP-1559 交易（类型 2）
```
chainId               11155111（Sepolia）—— 签名绑定链号，不能拿去别的链重放（EIP-155）
nonce
maxPriorityFeePerGas  给出块者的小费上限
maxFeePerGas          基础费 + 小费 的总上限
gasLimit              ERC-20 transfer 约 5 到 7 万（★ LINK 实测 51 658）
to                    代币合约地址 —— 不是收款人！收款人在 data 里
value                 0 —— 转的是代币，不是 ETH
data                  a9059cbb ‖ 收款人 ‖ 金额        ← transfer(address,uint256) 的 calldata
accessList            []
yParity, r, s         签名
```
交易字段里的 `to` 是合约；Transfer 事件参数里的 `to` 才是收款人，两个「to」不是一回事。

### 3. gas 的三个数
- **基础费**由协议按上一块的拥挤程度算出、每块变、**烧掉**；**小费**给出块者，决定排队位置。
- 签的是两个**上限**：实付单价 = min(maxFee, baseFee + maxPriority)，多设的退回。基础费每块最多涨 12.5%，所以 maxFee 取「2 × 基础费 + 小费」能扛几分钟的上涨，又不会真的多付。
- `gasLimit` 设低了，执行到一半 out of gas：**gas 照扣、状态回滚**。所以先 `eth_estimateGas` 再加两成。估算会失败——热钱包代币不够时直接 revert，这是好事：**花 gas 之前**就知道发不出去。

### 4. 序列化与签名
- **RLP**：一个字节串或一个列表，前缀说明长度。交易按字段顺序排成列表、RLP 编码，前面拼上类型字节 `0x02`。
- **签名哈希** = Keccak-256(`0x02` ‖ RLP(前九个字段))，不含签名本身。
- **ECDSA over secp256k1**：k 由 RFC 6979 从消息与私钥**确定**地算出，不用真随机（两笔撞同一个 k 就能解出私钥，PlayStation 3 的事故）；s 取 **low-s**（≤ n/2，EIP-2，否则同一个签名有两个合法写法、交易哈希不唯一）；
  **yParity** 让验证方从 (r, s) 反推公钥——交易里没有 from 字段，from 是从签名恢复出来的。
- **交易哈希** = Keccak-256(整条带签名的原文)，广播前就能算出来——「先落库再广播」的基础。

### 5. 交易的一生
```
签好 ─→ 广播（eth_sendRawTransaction）─→ 在节点内存池里 pending
                                         ├─→ 被打包进块：MINED，有回执（status 1 成功 / 0 回滚）
                                         │      └─→ 块被重组掉：回到 pending，或被同 nonce 的另一笔取代
                                         ├─→ 一直没人打包（费率太低）：卡单
                                         └─→ 被节点丢弃（内存池满、太久）：dropped，链上什么都没有
```
- **回执 status 0 也是上链了**：nonce 用掉了、gas 扣了、代币没动。对出账是「失败但已终结」，钱要解冻。
- **同一个 nonce 只能有一笔上链**。加速（同 nonce 更高费率）和取消（同 nonce 转 0 给自己）都是用新的挤掉旧的，节点要求新费率至少高 10%。
- **广播按内容幂等**：同一份签好的原文再发，节点回 already known，不会变成第二笔——重启后重发是安全的，前提是**留着原文**。

### 6. 热钱包
收款地址的私钥不在服务器上（`m3-payin.md`），钱到了那里服务器只能看不能动；要往外付，就得有一把服务器能用的私钥——**热钱包**，整个系统里最危险的东西（Ronin 桥约 6.25 亿美元就是私钥被拿走）。
原则（OWASP Key_Management / Secrets_Management）：私钥只从环境注入，不进代码、镜像层、日志；热钱包只放近期要付的量，大头在冷端；一把私钥泄露的影响面要有边界——
所以热钱包**不能**是收款树的普通派生子密钥（xpub 加任意一个子私钥就能反推父私钥，一把热钱包私钥会带走全部收款地址）。

### 7. 复式记账里的出账：冻结、结算、解冻
入账是「链上先发生、账本后承认」；出账反过来，**账本先扣、链上后发生**，中间几分钟到几小时的不确定期里，钱既不能算商户可用、又还没真的离开平台，用冻结账户表达：

| 时点 | 借 | 贷 | 业务类型 | 幂等键 |
|---|---|---|---|---|
| 申请 | `user:acme:LINK` | `user:acme:LINK:frozen` | `WITHDRAWAL_FREEZE` | `withdrawal:<申请幂等键>:freeze` |
| 链上 FINAL | `user:acme:LINK:frozen` | `chain:custody:LINK` | `WITHDRAWAL` | `withdrawal:<提现 id>:settle` |
| 失败或拒绝 | `user:acme:LINK:frozen` | `user:acme:LINK` | `WITHDRAWAL_REVERSE` | `withdrawal:<提现 id>:reverse` |

「同一笔只结算一次」由幂等键的唯一约束守；「结算过的不能再解冻」由冻结账户不许为负守。

### 8. 出账风控（学 OKX 的提币流程，取能做的）
白名单地址（先登记，再提现）、单笔与当日限额、超限转人工核准、拒绝提到平台自己的地址（那是内部转账，不是提现）。冷却期与二次验证依赖用户会话与通知渠道，没做（第三节）。

### ★ 真环境演练实测
- 首笔 1 LINK：申请后 6 秒签编号 0 并广播，13 秒回执上链（gas 51 658，实付 2.04 gwei），13 分 35 秒两个节点 finalized 一致、结算——时间几乎都花在等 finalized。
- 并发：一轮签四笔，编号 1–4 连续，20 秒内全部上链；超单笔上限的一笔进待核准、核准后照发；拒绝的解冻，再核准回 409。
- 只由测试守、没在真链上演练的：热钱包代币不够的 revert（商户余额 ≤ 热钱包余额，账本先拒，造不出）；别处用了这把钥匙导致停发；kill -9 与卡单加价（真机造不出窗口）。

## 二、取舍

1. **热钱包私钥来源**：环境变量里的十六进制私钥（`CHAINPAY_PAYOUT_HOT_WALLET_KEY`），由离线工具从另一句助记词、或同一句的硬化账户 `m/44'/60'/1'/0/0` 算出，绝不用收款树里的账户。
   与 xpub 同一套注入方式；keystore 加口令多一层加密，但口令仍要注入；服务器持助记词自己派生违反「服务端没有助记词」。
2. **只做 EIP-1559**：Sepolia 与主网都支持；兼容 legacy 就是两套费率模型，卡单策略跟着翻倍。
3. **签名用 web3j 的 `crypto` 模块，外面一层薄包装**（RLP、EIP-1559 编码、签名与恢复）：先自写并过了全部向量，再改判用库——协议编码用库，测试是我们的、原样留作验收。
   只拿 `crypto`（不拿 core，排除 EIP-4844 的原生库 `jc-kzg-4844`），包装层不暴露 web3j 类型，换库只动这一层。库的解码器宽松，规范性由「拆回再编回必须逐字节相同」守。
   已知答案逐字取自 ethereum/tests 与 EIP-155 正文（`src/test/resources/vectors/README.md`）。
4. **编号在库里分配，先落库再广播**：事务里锁热钱包行、签名、写原文、编号 +1、提交，**提交之后才广播**；广播成功再改 BROADCAST。真相虽在链上，但「我打算发第 12 笔」这个意图必须先落库，重启才有据可依。
   每轮先对账：链上计数 C（`latest`，不用只代表一个节点的 `pending`）、库里的下一个编号 N、还没有任何尝试上链的编号数 U。
   C > N = 链上比我们分出去的还多，有人在别处用了这把私钥；N > C + U = 有分出去的编号没有尝试记录。两种都整把钱包停发，重启不算恢复。
   测试提醒：两个实例按同样顺序抢同一批提现，会先在提现行上串行——这种双实例测试证明不了热钱包行锁（拆掉行锁它仍绿）。
5. **广播的回答说不清就停发**：成功或 already known 算发出；没有 code 的传输失败下一轮重发同一份原文；nonce too low 先看节点认不认识我们这笔或兄弟尝试；其它带 code 的拒绝一律整把钱包停发、叫人。
   不自动填坑（跳号补发、以取消交易填坑），停下叫人：编号是全局的，一笔卡住后面全部卡住。
6. **费率**：小费 = max(节点建议, 地板 1 gwei)；总费率 = 2 × 基础费 + 小费，超上限（100 gwei）这一轮不发、等回落；gasLimit = 估算 × 1.2，超上限（20 万）说明交易不正常，判失败。
   估 gas 时节点带错误码拒绝（典型是 revert）= 这笔发不出去，判失败并解冻——编号还没分，不留坑。
7. **在途的钱放每商户每币一个冻结账户**：余额接口能给出 `frozen`；RLS 天然归属；冻结合计就是在路上的出账。
8. **gas 只记在 `payout_tx`**（`gas_used`、`effective_gas_price`），不进 LINK 账本：ETH 是平台成本，不向商户收。
9. **风控**：白名单必过；没定过限额 = 一律人工（fail-closed）；当日上限只算自动放行过的，等核准的不占额度（人核准时看得到全部）；平台自己的地址（任何收款地址、热钱包自己）登记时与申请时各拒一次。
   商户连接看不到别家的收款地址，所以「是不是平台地址」走系统身份、只回答是或否；没用 SECURITY DEFINER 函数：FORCE RLS 下它靠属主特权才成立（V22 的教训）。进程拆分会改这一处（web 不再持有系统身份）。
10. **卡单自动加价**：广播 3 分钟还没上链、节点还认着 → 同编号再签一笔，两个费率都取 max(市价, 旧 × 125%)：只按市价可能不到节点要的 +10%（被拒 underpriced），只按 +25% 可能仍低于此刻的基础费。
    加价后超费率上限就这一轮不加、等回落——旧的那笔仍在池里排队，没有损失，费率是瞬时的。节点忘了的（DROPPED）原样重发；同编号谁先上链谁算，其余 REPLACED。
11. **结算绑 FINAL，revert 也等 FINAL 才解冻**：「重组只碰链表不碰账本」不能只对入账成立；status 0 的回执也可能被重组翻掉，冻着的钱多等十几分钟比退错了强。
    MINED 之后主节点说那块的哈希变了 = 重组，退回 BROADCAST 继续等；两个节点的 finalized 都过了那块、且对它的哈希一致，才结算或解冻。

## 三、不做的

- **KMS / 多签**：热钱包私钥现在是一个环境变量。上主网、碰真钱之前的前提（`m6-process-split.md` 取舍 9）。
- **冷却期与二次验证**：依赖用户会话与通知渠道，本项目是 API key 体系；进程拆分之后再评估。
- **取消交易**（同编号转 0 给自己）：自动与手动都没有。它会占用同一个编号、和加价抢位置。
- **ETH 账本**：gas 只记在 `payout_tx`，热钱包的 ETH 不进账本、不对账；ETH 不够时表现为广播被拒 → 钱包停发。
- **热钱包余额上限告警、按在途笔数给发送封顶**：进程拆分之后。
- **归集**：人工把收款地址上的币转到热钱包（`m3-payin.md`）。
- **已知缺口**：发送任务签名前不复核白名单、限额、核准与冻结——worker 不能信 web 写进库里的行，进程拆分第 ③ 步修（CLAUDE.md「付款」）。
